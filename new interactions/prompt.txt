The peach sprite — the most important part
Render every peach pixel by pixel into an offscreen canvas (ImageData), then cache it. Never draw peaches live.

The peach is seen butt up. It's built as two overlapping lobes:

Front lobe: a tilted oval covering the right ~¾ of the fruit.
Back lobe: a circle that peeks out as a crescent on the left and top.
The dip at the top is where the two outlines meet. The cleft is the front lobe's left edge, a long "(" curve, which glows with a pale gradient. The colour runs from a deep crimson top, through pink, to a cream glow low on the cheek. The bottom sits slightly flat, and the whole surface is heavily dithered grain like a stippled print.

Use exactly this colour ramp and shading. Coordinates are normalised to the peach radius, with y pointing down.

const BL = { cx:-0.1, cy:-0.1, r:0.87 };                     // back lobe, circle

const qF = hypot(u/FL.rx, w/FL.ry);                  // 1 = on the front lobe's outline
const qB = hypot(nx-BL.cx, ny-BL.cy) / BL.r;         // 1 = on the back lobe's outline
// one fruit: smooth-min the outlines, crisp at the top (keeps the dip), soft round the bottom

const alpha = (Math.random() < a ? 0.82 : 0) + a*0.18;

t += V.glow*exp(-((nx-V.hx)**2 + (ny-V.hy)**2)/V.spread) + V.bias;
t -= 0.38*exp(-((nx-0.22)**2/0.09 + (ny+0.78)**2/0.05));   // deep crimson pools in the dip

  t -= (0.06 + 0.16*smooth(1.12, 1.0, qF)) * (1 - smooth(0.3, 0.8, ny));
}
const rimO = smooth(0.8, 1.0, q)*0.62;              // fuzz catches light at the outline:
t = t*(1-rimO) + (0.42 + 0.42*smooth(-0.5, 0.6, ny))*rimO;   // pink up top, cream at the base

Sprite size: radius in pixels = peach radius on screen × sres. Pad the canvas by r·0.27 + blur·2.6.
Coarse grain: keep sres below 1, sres = clamp(0.8 / (1 + blur·0.18), 0.3, 0.8). The grain then reads coarse like a print, and blurry sprites build fast.
Blur: blur each sprite by its depth-of-field amount (see below) using a hand-written 3-pass box blur on premultiplied RGBA, with box radius ≈ blur. Don't use ctx.filter, because Safari doesn't support it.
Cache: key the sprite cache by row, variety and blur. Round the blur to 0.5px under 3px, and to whole pixels above that. Build every sprite during layout, not mid-animation.
Camera, layout and grid
Coordinates: world x runs across, z runs into the screen (row 0 = front) and h is height. One grid cell is 1 unit, and the peach radius is R = 0.53 cells, so neighbours just touch.
Perspective: s(z) = F / (z + D0) with D0 = 2.6, and screenX = W/2 + x·s, screenY = horizon + camH·s − h·s.
Anchor everything to the in-focus row, z = 2:
Its scale is sFocus = W / 6.2, which gives about six peaches across (W / 3.3 on mobile). So F = sFocus·(2 + D0).
Row spacing comes from the front row: gap = 0.85 · 2R · s(0) and camH = gap / (s(0) − s(1)).
The focus row's peach centres sit at focusCY = 0.43·H (0.46 on mobile), so horizon = focusCY + 0.9·R·sFocus − camH·sFocus.
Rows: add rows until one is fully past the top edge (cap at 18). The two rows in front of the focus row are bigger and bleed off the bottom.
Columns: enough to cover the back row's width: half = ceil((W/2)/s(last) + 1), cols = 2·half + 1.
Stagger: honeycomb. Every other row shifts half a cell, with ±0.025 random jitter in x and z.
Culling: skip any peach fully off-screen sideways, or fully below the bottom edge.
Orientation: keep peaches upright with the butt up. Tilt only ±0.11 rad, and mirror 25% of them. Give each one a variety.
Seating:
Each peach sits on its flat base. Draw it at the contact point, then offset up by 0.9·R·s.
Draw a soft contact shadow underneath. It's a cached radial gradient (rgba(120,60,40,.55) → .25 at 50% → 0), sized 2.3·R·s wide and 0.34 of that tall. It widens with squash, and shrinks and fades as the peach lifts.
Draw order: back to front, all shadows first.
Depth of field (lens)
Each peach's blur combines two things:

// depth: circle of confusion ∝ |1/Df − 1/D|, normalised so the front row gets dofK px, far rows capped
const blurAt = z => Math.min(dofK*0.75,
  dofK * Math.abs(1/(focusZ+D0) - 1/(z+D0)) / Math.abs(1/(focusZ+D0) - 1/D0));

The middle four or so peaches of the focus row are crisp. The sides of every row go soft, the front rows are heavily blurred and the back rows melt away.

Motion
Intro — grouped perspective rows, then individual foreground rows:
Preserve all the smaller distant rows: they create the camera perspective. Do not cut the grid down to four rows. The distant fruit should arrive quickly in groups of three; the four larger near rows should arrive one row at a time, back to front.
Every peach starts fully above the top edge, at height (groundY + 2.6·R·s)/s + random·0.14 cells, with zero vertical velocity, and falls under gravity (34 cells/s²).
Use this exact delay calculation in seconds, with row 0 nearest the camera and rows = the total row count:

function entranceDelay(row, x, rows) {
  const nearRows = focusZ + 2; // focusZ = 2; rows 3, 2, 1, 0 enter individually
  const distantRows = Math.max(0, rows - nearRows);
  const distantBatches = Math.ceil(distantRows / 3);
  const batch = Math.floor((rows - 1 - row) / 3);
  const start = row >= nearRows
    ? 0.08 + batch * 0.09
    : 0.08 + distantBatches * 0.09 + (nearRows - 1 - row) * 0.14;
  const spread = row >= nearRows ? 0.006 : 0.012;
  return start + Math.min(Math.abs(x), 4) * spread + Math.random() * 0.012;
}

The farthest three rows start together, then the next three 90ms later. After the distant groups, each of the four larger rows starts 140ms after the previous one. The tiny within-row variation keeps the fall natural without stretching it into a long procession. On typical desktop and mobile viewports, all visible peaches should make their first landing in about 1–1.6 seconds after the sprite cache is ready.
Each fruit's opacity rises from 0 to 1 over 160ms after its start delay; apply the same opacity to its shadow. This mostly happens while it is still above the frame. Keep the actual fall from above, rather than fading a stationary grid into place.
While falling fast, stretch vertically: fall = clamp(−v·0.006, 0, 0.12), so y grows by fall and x shrinks by 0.6·fall.
On impact, add impact·0.075 to the squash velocity and a random wobble. Bounce once (restitution 0.28 if impact > 3), then rest.

Jelly springs per peach (semi-implicit Euler):
squash sq: sqv += (−320·sq − 9·sqv)·dt, clamped −0.32…0.36
wobble wob: wobv += (−200·wob − 7·wobv)·dt, clamped ±0.5
Drawing a peach:
Translate to the contact point and rotate wob·0.35.
Scale (1 + 0.75·sq − 0.6·fall, 1 − sq + fall).
Translate up 0.9·R·s, rotate rot0 + wob·0.6, mirror if flipped, then draw the sprite.
Hover:
Hit-test with circles, nearest rows first. Show a pointer cursor over a peach.
When the pointer enters a landed, resting peach, it hops: v = 6.5, sqv −= 4.2 (it stretches as it leaves) and wobv ±= 7. Give each peach a 0.32s cooldown.
Neighbours within 1.3 cells give a smaller, delayed hop: after 0.06 + d·0.05 s, with strength 0.32/d (v, squash and wobble scaled by it), so it spreads like a ripple.
Click: a 1.5× hop that ignores the cooldown.
Physics: run fixed substeps of ≤8ms per frame and cap dt at 0.1s, so timing is correct at any frame rate.
Reduced motion: peaches start already in place; hover only gives a gentle squash and wobble, no hop. The type appears without animation.
Resize: debounce it (120ms), then rebuild the projection, blur and sprites. Only re-lay the grid if the row or column count changes.
